# Rating Approach Report: Physics vs Tuning vs Reality

**Date:** 2026-03-26
**Context:** V3 topology at 250 MVA 138 kV, 1,195 MW shed. 41 lines upgraded 250→500 via iterative SCED congestion → 88 MW shed. Are there better approaches?

---

## Three Ways to Set Line Ratings

### 1. Conductor assumption (bottom-up)
Assume a conductor type → compute rating from IEEE 738.
- **Our current default:** 250 MVA = 795 kcmil Drake at 40°C/100°C.
- **Pro:** Physically grounded, reproducible.
- **Con:** We don't know which conductor any specific line uses. Real ERCOT 138 kV ranges from 148 to 838 MVA per ERCOT RPG filings — a 5.7× range from the same voltage tier.

### 2. SCED congestion iteration (what we're doing today)
Run SCED → find binding lines → upgrade them → repeat.
- **Pro:** Directly targets lines that cause shedding. Each upgrade is verifiable.
- **Con:** Circular — the binding set depends on the rating assumption. Each round reveals new bindings. We're on round 2 (41 lines); round 3, 4, 5... will follow. Also slightly ad hoc: "doubled because it was binding" doesn't have a physical justification for the specific target value (500 MVA).

### 3. Unconstrained DC power flow (Kirchhoff's laws)
Compute flows with no thermal limits, using economic dispatch. Any line where flow > assumed rating is provably underrated.
- **Pro:** One-shot, physics-based (Kirchhoff), no iteration needed. Identifies ALL underrated lines simultaneously.
- **Con:** Depends on the injection pattern (load + dispatch), which is approximate.

## What the DC Power Flow Actually Showed

I computed DC power flow on the v3 network with:
- Generation: renewables at Nov 5 CFs + thermal cheapest-first to meet remaining load
- Load: **uniform per bus within each zone** (not population-weighted — significant caveat)
- Network: v3 topology, v3 impedances, no thermal limits

**Result:** 105 lines where unconstrained flow > assumed rating.

| Zone | Lines overloaded | Interpretation |
|------|-----------------|----------------|
| HOUSTON | 47 | Huge — Houston is import-dependent (15 GW gen, 11.5 GW load) |
| NORTH | 35 | DFW — consistent with session findings |
| SOUTH | 13 | Hill Country corridors |
| WEST | 10 | Renewable export paths |

### Critical caveat: load distribution

The DC analysis used **uniform** load per bus. The real SCED uses **population-weighted** load. This is a big difference:
- Uniform puts too much load in rural areas → finds false bottlenecks on rural lines
- Uniform puts too little load in DFW core → misses real DFW bottlenecks
- Houston analysis is most affected: the 47 "overloaded" Houston lines include many that serve rural areas that in reality have much less load

**The 105 lines from DC flow are NOT a superset of the 41 SCED-upgraded lines.** They're a different set generated by a different load assumption. There is overlap (both methods find lines in urban import corridors), but the DC analysis has false positives in rural areas and false negatives in urban cores.

### Can we fix this?

Yes — run the DC power flow with the same population-weighted load that run_sced.py uses. Or better: run a "floor" SCED experiment on v3 (all ratings 999,999) and read the line flows from line_detail.csv. That gives the unconstrained flows with the correct SCED dispatch and load allocation, no approximations.

## Why Matching ERCOT Shadow Price Data Doesn't Work (Yet)

The ERCOT_SCED_Shadowprices.csv data has two problems:

**1. The Limit field isn't a static line rating.** It's the Ambient Adjusted Rating (AAR) — we see the same line's limit changing 213→222 MW across a single hour as temperature fluctuates. And under contingency conditions, the same physical line appears with different limits (BR→HOC: 485 MW base case, 634 MW under contingency SMDOOAS5).

**2. Many "constraints" are flowgates, not individual lines.**
- WESTEX: Limit = 10,225 MW — that's the aggregate West Texas export corridor, not any single line
- NE_LOB: Limit = 1,594 MW — a nomogram, not a branch
- These don't have From/To station names

From the one hour of data we have, only ~8 unique 138 kV individual-line base-case constraints appear. We'd need months of data across many operating conditions to build a comprehensive rating table. And the station name matching (BCKSW, CGRSW, ODNTH → OSM names) would be lossy.

## The Missing Line Question

Are the 105 "overloaded" lines actually underrated, or are we missing parallel paths?

**Evidence for missing parallel paths:**
- We capture 81% of ERCOT circuit-km. The missing 19% likely includes parallel lines on high-traffic corridors.
- L170_185_138 (Booster→Seadoc, Houston) carries 1,579 MW through a 500 MVA rating. Getting 1,579 MVA from a single 138 kV line would require 6,600A — physically impossible. The real system almost certainly has 3-4 parallel circuits here.
- Urban areas have the densest parallel circuits AND the most OSM mapping gaps (underground cables, shared rights-of-way mapped as single features).

**Evidence against (some really are underrated):**
- The session's 28 binding DFW lines all have `cables=3` in OSM — they ARE single circuit, not missing parallels.
- Our E/N ratio of 1.348 at 138 kV exceeds real ERCOT's 1.182 — aggregate connectivity is fine.
- The ERCOT RPG filings show single-circuit 138 kV lines rated at 478-838 MVA, meaning the 250 MVA Drake assumption underestimates many real lines.

**The honest answer:** It's both. Some lines need higher ratings (larger conductors than Drake). Some corridors need more parallel paths. We can't distinguish the two without CEII data. But the practical effect is the same: our model needs more flow capacity on ~100 specific corridors.

## Are the 105 DC Lines the Same as the 41 SCED Lines?

I couldn't do exact UID matching (different branch.csv builds on adroit vs local). But conceptually:

**They partially overlap but are NOT identical.** Here's why:

| Effect | DC power flow (unconstrained) | SCED (constrained) |
|--------|-------------------------------|-------------------|
| Dispatch | Pure economic (cheapest first) | Economic + respects limits |
| Load | Uniform within zone (my approximation) | Population-weighted |
| Flow pattern | "Natural" Kirchhoff routing | Redispatched around congestion |
| Lines found | All structurally overloaded | Only the binding constraint set |

In the constrained SCED, when line A binds, the optimizer redispatches to route power around it. This can INCREASE flow on line B (which then binds in round 2). So the SCED approach discovers lines sequentially (A first, then B, then C...) while the DC approach sees them all at once — but with a different (less accurate) load pattern.

**Prediction:** If we ran the "floor" SCED on v3 (all ratings at 999,999) with population-weighted load, the overloaded line set would be smaller than 105 (because pop-weighted concentrates load in fewer buses) and would overlap more strongly with the 41 SCED lines.

## Recommendation

### Immediate: Run a v3 "floor" experiment

Submit a v3 SCED with all ratings at 999,999 MVA (BRANCH_SCALE=0). Read line_detail.csv. This gives us:
- Unconstrained flows with the CORRECT load allocation and dispatch
- A physics-based lower bound on every line's rating
- No approximations (unlike my DC analysis with uniform load)

Then: for every line where unconstrained_flow > 250 MVA, set the rating to `min(unconstrained_flow × 1.1, 800)`. The 1.1× margin is for the fact that the unconstrained dispatch slightly differs from the real constrained dispatch. The 800 MVA cap is the observed ERCOT upper bound for 138 kV single-circuit lines.

This replaces the iterative SCED rounds (1, 2, 3, ...) with a single physics-based correction. It's principled (Kirchhoff's laws), bounded (cap at physical max), and one-shot (no iteration).

### Why this is better than what we're doing

| | Iterative SCED | Floor-based correction |
|---|---|---|
| Rounds needed | 3-5+ | 1 |
| Physical basis | "It was binding" | Kirchhoff flow lower bound |
| Target value | 2× (arbitrary) | flow × 1.1, capped at 800 (bounded) |
| Covers all bottlenecks | Eventually (if patient) | All at once |
| Load distribution | Correct (pop-weighted) | Correct (same SCED) |

### What this does NOT fix

- Lines where we're missing parallel paths (19% of km unmapped) → these still need higher effective ratings
- The conductor assumption for non-overloaded lines → 250 MVA remains the default
- WESTEX handling → Morgan Creek→Tonkawa stays at 1,200 MVA regardless

### Longer term

The floor-based approach is a principled first step. The deeper fix would be:
1. Download months of ERCOT binding constraint data (NP6-86-CD)
2. Build a lookup of (from_station, to_station) → observed AAR limit
3. Match to OSM substations where possible
4. For matched lines, replace our conductor assumption with the observed ERCOT rating

This is messier but would give us ground truth for the ~50-100 most important lines in the ERCOT system.
